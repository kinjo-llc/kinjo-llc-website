# Kinjo LLC AI Operating Manual

NOTE:
The canonical version of this document lives in the Kinjo LLC Studio Brain in Google Drive.

This repository copy exists to provide engineering context for developers and AI tools.


Kinjo LLC AI Operating Manual
Canonical Document – Studio Brain
Purpose
This document defines how Kinjo LLC uses artificial intelligence systems to operate the company.
It establishes:
AI roles


company knowledge structure


engineering workflows


collaboration rules


onboarding guidance for team members


The goal is to create a structured, multi-AI operating environment where tools support human decision making while preserving accountability, security, and clarity.

1. Company Overview
Kinjo LLC is a mission-oriented company focused on:
government and defense contracting


international cooperation and operations


intelligence, analytical, and advisory capabilities


future development of AI-enabled tools and systems


The company combines human expertise with structured AI assistance to increase operational capability while maintaining professional standards required for government work.
AI tools are used to support:
planning


documentation


engineering


research


operational organization


Final decisions and accountability always remain with human leadership.

2. AI Operating Model
Kinjo LLC currently uses multiple AI systems that perform different roles.

strategy


architecture


planning


documentation


company context management

system architecture

Google Drive (Studio Brain)

company knowledge storage

3. Memory Architecture
Kinjo LLC uses a layered memory model.
Canonical Company Knowledge
Location:
Google Drive → Studio Brain
Examples:
company context


operating manuals


project plans


strategic documents


This is the source of truth for the company.

Engineering Context
Location:
GitHub repository
Examples:
code


development documentation


engineering instructions


system architecture notes


This allows engineering tools and developers to understand system structure.

AI Operational Context
Location:
Repository folders such as:
ai-ops/
.claude/
These provide instructions for AI systems working on the repository.
They help ensure that AI tools follow company rules when making changes.

Collaboration Context
Location:
ChatGPT Business workspace
This workspace allows team members to:
collaborate


generate drafts


analyze information


develop plans


Important:
The ChatGPT workspace is not automatically the company memory.
Important information must be promoted into the company canon in Drive.

Private Workspaces
Team members may maintain private notes and private AI chats.
These are used for:
personal thinking


draft work


experimentation


sensitive notes


Private workspaces are normal and expected.
Only approved information should enter company memory.

4. Knowledge Promotion Rules
Information does not automatically become company knowledge.
The promotion process is:
Working notes
↓
Review
↓
Approved information
↓
Added to company canon
↓
Mirrored to engineering docs if needed
This prevents knowledge chaos and keeps company memory reliable.

5. Engineering Workflow
Software development follows this pipeline:
Development work
↓
GitHub branch
↓
Preview deployment
↓
Testing
↓
Production deployment
Preview environments ensure the production system remains stable.
Repository folders such as ai-ops and .claude provide AI systems with instructions about the project.

6. AI Usage Rules
When using AI tools within Kinjo LLC:
Sensitive government data should never be uploaded to AI systems.


Company canonical documents must remain organized in the Studio Brain.


Duplicate “truth documents” should not be created.


Engineering changes must follow repository rules.


AI outputs should be reviewed before being accepted as company information.


AI tools assist operations but do not replace human responsibility.

7. Collaboration Guidelines
Team members working with AI systems should:
read the company context first


work within defined project spaces


summarize outputs clearly


avoid duplicating knowledge sources


promote useful knowledge to the company canon


Clear documentation improves the effectiveness of AI assistance.

8. Jason Onboarding Context
Jason will operate within the Kinjo LLC AI system.
His responsibilities include:
participating in company planning


contributing ideas and research


helping develop projects and partnerships


assisting with operational tasks as assigned


Jason may maintain private notes but should contribute important findings to the shared workspace when appropriate.
Final authority for company direction remains with Kinjo LLC leadership.

9. Current System Status
Kinjo LLC currently operates with:
a structured AI workflow


a shared company knowledge system


an engineering repository with AI instructions


a preview-safe deployment pipeline


a growing operational framework


The system will evolve as the company grows.

10. Future Development
Planned improvements include:
expanded company knowledge base


deeper integration between AI tools


improved project documentation


development of internal AI tools and systems


These efforts will gradually move Kinjo LLC toward a fully integrated AI-assisted operating environment.

End of Document
